# Качество анализа комментариев

В `backend/data/quality/feedback.csv` находятся 40 вымышленных анкет. Для
каждой вручную заданы ожидаемая тональность и проблемные темы. Среди примеров
есть прямые и вежливые жалобы, сарказм, жалобы наставника, положительные ответы
и пограничные случаи вроде «Задач много, но сроки нормальные и я справляюсь».

Из папки `backend` запустите офлайн-проверку текущих правил:

```bash
python -m app.quality
```

При настроенном GigaChat можно явно запустить такой же прогон через API или
выбрать отдельные анкеты. Передавайте только вымышленные данные:

```bash
python -m app.quality --provider gigachat --case 01 --case 02 --case 03
python -m app.quality --provider gigachat
```

В отчёте выводятся фактическая версия модели, версия промпта, доля успешных
разборов и расхождения по ID случаев. Для R1 проверка использует рабочие правила
проекта. Ожидаемый флажок задан высокой оценкой (4 или 5) и размеченной жалобой.
Точность показывает, какая доля выданных R1 подтверждается разметкой. Полнота
показывает, какая доля ожидаемых R1 обнаружена. Ошибки API учитываются отдельно
от качества успешно обработанных случаев.

Офлайн-провайдер `mock` обработал 40 из 40 примеров. Он подтвердил два
ожидаемых R1, ошибочно выдал два и пропустил 18. Точность R1 — 50%, полнота —
10%. Совпали 35% наборов проблемных тем и 25% меток тональности.

В прогоне от 21 ноября 2026 года GigaChat `2.0.28.2` с промптом `v3`
обработал 40 из 40 анкет. Правило R1 сработало в 18 из 20 ожидаемых случаев
и не сработало во всех 20 контрольных. Точность — 100%, полнота — 90%.
Проблемные темы совпали полностью в 35 из 40 случаев, тональность — в 30 из 40.
Два пропуска R1 — случаи `14` и `15`. Результат описывает этот набор
вымышленных анкет.

Состояние фоновой обработки доступно в `GET /api/analysis/queue`. API
показывает количество ожидающих, выполняющихся, зависших и неудачных попыток,
время поступления старейшей ожидающей анкеты и момент последней окончательной
ошибки, если она есть. В карточке стажёра пользователь с правом записи может
повторно запустить анализ одного ответа.

Временные ошибки связи, ограничения частоты и ошибки провайдера 5xx
возвращают анкету в очередь. Обработчик делает до трёх фоновых попыток с
интервалами в 15 и 30 секунд. После аварийной остановки обработчика запись
становится доступной другой попытке по окончании срока обработки.

## GigaChat: замер 24 ноября 2026

Модель `GigaChat-2` (2.0.30.01), промпт v6, `temperature` 0,01. 40 вымышленных
анкет разделены пополам: по 20 нечётным исправляли промпт, 20 чётных не
просматривали и прогнали один раз после заморозки промпта.

| Отложенные 20 анкет | mock | GigaChat-2 |
| --- | --- | --- |
| R1: найдено жалоб с высокой оценкой | 0 из 9 | 8 из 9 |
| R1: ложные срабатывания | 1 | 0 |
| Верная тональность | 5 из 20 | 18 из 20 |
| Точное совпадение тем жалобы | 8 из 20 | 17 из 20 |
| Не разобрано | 0 | 1 |

Неразобранная анкета считается ошибкой во всех строках. После замера изменили
обработку этого случая: если цитату подтвердить не удалось, разметка сохраняется
без цитаты и с уверенностью не выше 0,35. Отложенную часть заново не прогоняли.

Ограничения: выборка маленькая, анкеты вымышленные и размечены командой.
Отложенная половина независима только от правок v5 → v6: более ранний промпт
составлялся при известных 40 анкетах и измерялся на них (v3, 21 ноября). Поэтому
это не оценка на новых данных: для неё нужны свежие анкеты. Был один
прогон, ответы модели немного меняются от запуска к запуску. Прогон оценивает
разметку модели без анонимизации и без страховки `_guard_remote_result`. Тонкий
сарказм («Спасибо за оперативность, доступы снова открыли в день сдачи») модель
на настроечной половине не распознала.

Чтобы повторить, нужен ключ и корневой сертификат Минцифры (см. README). Имя
модели зависит от адреса: на `api.giga.chat` нет `GigaChat`, есть `GigaChat-2`.

## Слепой замер 24 ноября 2026 — эту цифру и показываем

30 новых вымышленных анкет (`backend/data/quality/blind_2026_11_24.csv`) написал
ИИ-агент без доступа к промпту и прежним анкетам. Два других ИИ-агента разметили
их независимо: наличие жалобы совпало в 30 из 30, темы — в 28, тональность — в 29.
Один прогон всего пути (анонимизация → `GigaChat-2`, промпт v6 → страховка).
Где разметчики расходятся, указаны оба значения.

| 30 слепых анкет | mock | GigaChat-2 |
| --- | --- | --- |
| Жалоба найдена | 3 из 16 | 13 из 16 |
| R1: жалоба при оценке 4–5 | 3 из 11 | 8 из 11 |
| R1: ложные срабатывания | 2 из 11 | 1 из 11 |
| Верная тональность | 8–9 из 30 | 19–20 из 30 |
| Точное совпадение тем | 14 из 30 | 17 из 30 |
| Не разобрано | 0 | 3 |

Все три неразобранные анкеты: модель назвала тему не из списка. Они засчитаны как
ошибки. После замера такая тема сводится к `other`; замер не повторяли, потому что
набор уже не слепой. Модель пропускает сарказм и жалобу внутри восторженного
отзыва, добавляет лишние соседние темы.

Анкеты и разметку делал ИИ, людей среди разметчиков не было. Для пилота нужны
реальные анкеты с согласия участников и разметка HR.
